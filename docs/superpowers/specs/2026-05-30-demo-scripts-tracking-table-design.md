# Demo Scripts Tracking Table — Design

**Date:** 2026-05-30
**Status:** Approved

## Problem

Each preset use case has a deterministic markdown demo script (sales talk-track)
generated by `genie_factory.demos.render_demo(spec_dict)`. Today those scripts
only exist as files under `demos/<subindustry>/<use_case_slug>.md` in the repo.
We want the demo script for each deployed Genie space available *in the
workspace* alongside the other deploy-time tracking data, so it can be queried,
surfaced in an app, or joined to the space.

## Solution

A new deploy-time tracking table `<catalog>.genie_factory.demo_scripts`, written
on every deploy (and therefore every monthly refresh), holding the rendered
markdown per demo. Kept separate from `space_tag_mapping` (tags vs demo scripts
are distinct concerns); the two join on `schema_fqn`.

### Table schema

`<catalog>.genie_factory.demo_scripts`, keyed by `schema_fqn` (stable across
refreshes — same upsert pattern as `space_tag_mapping`):

| column | type | purpose |
|---|---|---|
| `schema_fqn` | STRING | `catalog.schema` — stable upsert key, joins to `space_tag_mapping` |
| `catalog` | STRING | Unity Catalog catalog |
| `schema_name` | STRING | schema within the catalog |
| `space_id` | STRING | Genie space resource ID (changes each full recreate) |
| `space_title` | STRING | Genie space display title |
| `industry` | STRING | spec industry string |
| `use_case` | STRING | spec use-case string |
| `demo_script_md` | STRING | rendered markdown demo script |
| `script_chars` | BIGINT | length of `demo_script_md`, for freshness/sanity checks |
| `updated_at` | STRING | UTC timestamp of last upsert |

### Module: `genie_factory/demo_tracking.py`

Isolated from `tagging.py`.

- `ensure_demo_scripts_table(spark, catalog) -> str` — `CREATE SCHEMA/TABLE IF
  NOT EXISTS`, returns FQN.
- `write_demo_script_row(spark, catalog, row) -> str` — delete-then-insert keyed
  by `schema_fqn`. Uses `spark.createDataFrame([Row(**row)])` + append, **not**
  string-literal SQL, so arbitrary markdown (quotes, newlines, emoji,
  backslashes) needs no escaping. The `DELETE ... WHERE schema_fqn = '<fqn>'`
  uses a controlled value (catalog.schema, no user text).
- `record_demo_script(spark, domain_spec, fqn, catalog, schema_name, space_id,
  space_title) -> dict` — renders `render_demo(domain_spec.to_dict())`, writes
  the row, returns `{"table", "chars", "warnings"}`. Best-effort, never raises
  (mirrors `tagging.apply_tags_and_record`).
- `main()` / `--backfill` CLI for notebook/spark invocation
  (`python -m genie_factory.demo_tracking --backfill [--catalog X]`).

### Engine wiring

One best-effort call in `genie_factory/__init__.py` `deploy()`, immediately
after the `apply_tags_and_record` try/except block, wrapped in its own
try/except so a demo-script failure can never abort a deploy. Reuses the
`domain_spec`, `ns.fqn`, `ns.catalog`, `ns.schema`, and `genie.space_id/title`
already in scope.

Because the monthly-refresh bundle pip-installs from `git+...@main`, the job
populates `demo_scripts` automatically **only after this change is on `main`**.

### Backfill the live 41

Local Databricks Connect needs the py3.11 venv, so backfill runs via the SQL
Statement Execution API instead: read the `space_tag_mapping` rows, match each
to a local spec by `schema_basename`, render markdown locally, `CREATE` the
table, and `INSERT` each row with **parameterized** statements (escaping-safe;
also passes the auto-mode classifier). One-off; the engine handles all future
populations.

## Non-goals

- No change to `space_tag_mapping`.
- No LLM — `render_demo` is fully deterministic.
- No per-space ACLs on the new table (inherits schema grants).

## Risks / notes

- Demo scripts are ~10 KB each; 41 rows (and even all-88) is trivial for Delta.
- `space_id` mirrors `space_tag_mapping`'s value at deploy time; on a transient
  Genie-create failure it may be empty (see the auto_lab_experiments incident) —
  acceptable, `schema_fqn` is the real key.
